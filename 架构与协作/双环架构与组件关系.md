# OctoLoop 双环架构与组件关系(AGENT 知识)

> 维护日期:2026-10-21 · 依据:本机 dora 项目一次双 PR 战役的完整实战
> 权威规程永远以 `/home/dora/octoscode/docs/` 下文档为准,本文是实战速览。

---

## 1. 一句话总览

**OctoLoop = "外环强模型审查 + 内环便宜模型执行"的双环协作框架。**
外环(Claude Code)只做派单、审查、复验、代推;内环(octoscode / codex 车道)只做读黑板、干活、commit、写 ACK。**推送权永远在外环**,每个 commit 过两双眼睛。

## 2. 四个组件分别是什么

| 组件 | 是什么 | 在本机的位置/版本 |
|---|---|---|
| **`/octoloop`** | Claude Code 的 skill(产品化入口),三模式:`init`(铺脚手架)/ `outer`(外环上岗)/ `inner`(内环形态选型)。本身不跑进程,是协议与纪律的载体 | `.claude/skills/octoloop` |
| **`octoscode`** | 内环 **TUI**(对话界面),底下经 `--stdio-command 'octos serve --stdio --solo'` 拉起 **octos serve** 后端(UI Protocol v1 over stdio) | octoscode **0.3.1**(与 octos v2.0.3 配对发布);octos serve 由本地源码 `/home/dora/octos`(main,v2.0.3+31)构建 |
| **`herdr`** | 终端**工作区管理器**:session → workspace(space)→ tab → pane 四级容器;自动识别 pane 里跑的编码 agent(codex/pi/claude…),侧栏显示状态(working/blocked/done/idle/unknown),支持 `agent prompt` 直投 | herdr **0.9.5**(尚无 octoscode 识别,需 feat/octoscode-agent 分支) |
| **AGENT** | 两层含义:①各环上的 **agent 实体**(外环 Claude Code 会话及其子代理、内环 octoscode/deepseek、codex 车道);②仓库里的 **`AGENTS.md`** —— 落地项目的常驻约束信道(自包含上岗卡,agent 读它即上岗) | codex-cli **0.163.0**(GPT-6-Sol);octos 内环主车道 **deepseek-chat** |

## 3. 内外环的关系

```
┌─ 外环(审查侧,强模型)─────────────────────────────┐
│  Claude Code 会话(本文件作者)                      │
│   ├─ 子代理:/code-review fork、CI 哨、黑板 ACK 哨    │
│   └─ 职责:读黑板→派编号单→唤醒内环→独立复验→采认→代推 │
│         ▲                          │ herdr agent prompt / pane send-text
│   .octos/OUTER_LOOP_REVIEW.md(黑板)  ▼
└─ 内环(执行侧,便宜模型)─────────────────────────────┘
   ├─ octoscode 标准车道(herdr w1:p2,deepseek,octos serve stdio)
   └─ codex 免审批窗格(herdr w1:p3 / w1:p4,快轨修订与交叉审查)
   职责:读黑板→执行→只 commit 绝不 push→写 ACK(done|wontdo|blocked)

operator(键盘后的人):只做 agent 永不代劳的四件事——
  贴 API key、免沙箱授权(--danger-full-access / 权限第 5 档)、
  接管 outer-duty 锁、发布 issue(以及 PR 的 Trunk 合并提交)。
```

**关键纪律**:
- 黑板协议:派单只追加、不改写;改判必须落在**新的未 ACK 条目**(R1/R5);ACK 定式一行。
- R2 诚实声明:每个交付注明 `verified` / `partially-verified` / `unverified`,写清跑了什么。
- 树主权:主工作树一次只属一个 goal;并行车道各占独立 worktree;非 owner 不 checkout。
- 复验独立:内环自证不可信,外环在**隔离 worktree** 用与 CI **逐字一致**的命令重跑(血案:新旧门禁差 `--all` vs `--all --all-targets` 导致本地绿/CI 红一次)。
- 双签终审:切片级以上交付,另一厂牌/另一车道对抗复审("验收的验收")。

## 4. 通信与观测面

| 目的 | 手段 |
|---|---|
| 投任务给被识别 agent | `herdr agent prompt <name> '<text>'`(codex 可用) |
| 投任务给未识别 agent(octoscode) | `herdr pane send-text <pane> '<text>'` + `send-keys enter` |
| 看现场 | `herdr pane read <pane>`(屏幕)、`herdr agent list`(状态)、`octos goal status --json`、会话 ledger |
| 黑板正信号哨 | `~/.octos/outer/watch-board.sh <板> 'ACK(done' --skip-signature <自己署名>`(尾部追加基线,落板后挂;ACK 写在条目中部会漏报——复验时人工核板) |
| 负信号哨 | octos 会话 `events/ledger` 的 goal_transition blocked / escalation(只盯正信号分不清"熔断沉默"与"还在干活") |
| 外环写黑板 | `~/.octos/outer/board-append.sh <板>`(flock 原子追加) |

## 6. 一次完整战役流水线(双 PR 实录)

```
PR 冲突(CONFLICTING)
 → 外环预演 merge(临时 worktree)→ 派单黑板
 → 内环车道:reset/merge/修冲突 → 验收四条 → commit → ACK
 → 外环:隔离 worktree 逐字复验 + diff 双向审查 → 采认判词 → 代推 fork
 → CI 哨 → 红 → 根因(log-failed 拿行级修法)→ addendum 派回车道 → 再循环
 → 交叉审查(另一车道只读审对方成果)→ 发现 → 派修 → 再循环
 → CI 双绿 + mergeable → 收官:只剩维护者 Trunk 提交
```

实绩:2 PR、13 项缺陷修复、6 次复验代推,CI 零红收尾;黑板 15 条记录全链可溯。

## 7. 实战坑位清单

1. **哨误报**:自己的条目正文里别提前写 ACK 格式字样;"先落板后挂哨";谓词别命中自己说的话(FIX-DONE 字样误报一次)。
2. **哨漏报**:watch-board 只看**尾部追加**,ACK 写在条目中部抓不到 → 复验时人工核板。
3. **门禁漂移**:CI 门禁会随 main 变(新版加了 `--all-targets`);复验命令必须与 CI 逐字一致。
4. **打断恢复**:codex 车道被 Esc 打断 = 进程活着、暂存无损;resume prompt 让它从自己上下文续跑即可(58s 收官实案)。
5. **herdr 引号**:`pane run` 会拍平引号;带引号的命令用 `send-text` 打字。
6. **权限档 1-4 是 bwrap 沙箱**(cargo 不可见),不是审批开关;要工具链 = 第 5 档/`--danger-full-access`。
7. **会话键**:`<profile>:local:<name>`(如 `deepseek:local:tui#coding`),`--session` 可直开既有会话。
8. **并发限载**:车道并行时编译 ≤2、测试 `--test-threads=8`。

## 8. 速查命令

```bash
# herdr
herdr agent list / get <name>                    # agent 状态
herdr agent prompt <name> '<text>'               # 投任务
herdr pane list / read <pane> / send-text / send-keys <pane> enter
herdr pane split --pane <p> --direction right --cwd <dir>   # 开新车道窗格
herdr agent start <name> --kind codex --pane <p>            # 起 codex 车道

# 黑板
~/.octos/outer/board-append.sh /path/OUTER_LOOP_REVIEW.md   # 派单(原子追加)
~/.octos/outer/watch-board.sh <板> 'ACK(done' --skip-signature '外环(claude)'

# 内环 TUI
octoscode --stdio-command 'octos serve --stdio --solo --danger-full-access --config ~/.octos/config-local.json' --profile-id deepseek --cwd <dir>

# 复验(隔离 worktree + 与 CI 逐字一致)
git worktree add ~/.octos/outer/verify/<名> <commit>
CARGO_TARGET_DIR=<共享缓存> PYO3_PYTHON=/usr/bin/python3.11 \
  cargo clippy --all --all-targets --exclude dora-node-api-python \
  --exclude dora-operator-api-python --exclude dora-ros2-bridge-python -- -D warnings
git worktree remove --force ~/.octos/outer/verify/<名>       # 验后即清
```
